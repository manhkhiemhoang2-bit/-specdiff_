# 示例：对真实项目的波形做规格检查

这里用的是一份真实项目的仿真波形——一个 3×3 窗口几何模块，96 位数据通路、32×8 图像、两帧。

波形来自 ModelSim，150 个时钟周期、61 个信号、24440 次跳变。

## 规格从哪来

`win3x3.spec.yaml` 里的契约从接口协议推导，没有读 RTL 实现：

| 契约 | 内容 | 出处 |
|---|---|---|
| A | 四个握手信号逐拍精确延迟 2 拍 | 接口时序规格 |
| C | 有效拍上 `O_window` / `O_tdata` 不允许出现 x/z | 不定态传播要求 |
| D | `O_window_valid` 上 X 不得漏到输出 | 行缓冲复位行为 |

## 运行

```bash
specdiff check win3x3.vcd win3x3.spec.yaml -v
```

输出：

```
通过：6 条契约、876 次断言全部满足（146 个有效周期，前 4 拍因复位屏蔽）
```

这 876 次断言全部落在真实数据上。

## 证明这些断言不是摆设

```bash
specdiff check win3x3.vcd win3x3.spec.yaml --selftest
```

```
变异自检：故意改错规格，每条都必须被抓出来
（抓不住的条目说明这个维度没测到东西）

  延迟多算一拍                       报错   50 条   抓住
  延迟少算一拍                       报错   50 条   抓住
  适用条件取反                           无法验证   —— 本数据里该契约从未被违反
  公式改成不可能值                            不适用   —— 规格里没有这类规则
  注入 X 到 O_tdata               报错    1 条   抓住
  注入 X 到 O_window              报错   11 条   抓住
  注入 X 到 O_window_valid        报错   11 条   抓住

鉴别力：5/5 个变异被抓住  -> PASS
```

这里有两点要说明。

延迟断言确实在起作用：把"2 拍"改成 1 拍或 3 拍，立刻报出 50 处不符，不是碰巧通过。

`no_x` 只能靠注入 X 来验证。原始波形里一个 X 都没有，怎么改规格都测不出差别，所以自检往波形里塞了一个 X，确认能被抓住。注入 O_tdata 报出 1 处，注入 O_window 和 O_window_valid 各报出 11 处。

## 和项目自带检查脚本的分工

真实项目里通常已经有一个自研检查脚本（比如 `check_win3x3.py`），做的是几何反解：从波形里的字节值反推源像素坐标，验证 3×3 窗口的 36 个抽头各自对应哪个位置。

这套逻辑依赖唯一值图和坐标映射公式，是项目专有的，不适合塞进通用工具。合理的分工是这样：

| 检查内容 | 放在哪 | 理由 |
|---|---|---|
| 延迟、握手稳定性、不定态 | specdiff | 通用契约，任何项目都一样，而且能定位到 bit |
| 几何反解、坐标映射 | 项目自己的脚本 | 依赖项目专有的数据构造方式 |

这样换项目时通用部分能直接复用，项目专有逻辑仍由最懂它的人维护。
