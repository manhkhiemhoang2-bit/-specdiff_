# specdiff

按规格检查仿真波形，直接告诉你第几拍、哪个信号、哪几位错了。

大模型会写 RTL，但看不见波形。仿真报错时它只知道"不匹配"，不知道错在第几拍、哪根线、哪一位，只能靠猜，一轮一轮地试。specdiff 把百万级的波形数据压成一句定位：

```
第 3 拍发现不一致：tb.dut.count（期望 0x01，实际 0x09，第 3 位不同）
```

## 两条路

| 命令 | 输入 | 什么时候能用 |
|---|---|---|
| `check` | 波形 + 规格 | 第一版设计就能用，不需要参照物 |
| `diff` | 波形 + 标准答案 | 手上另有一份已知正确的数据 |

`check` 不需要先有一份"正确波形"，只要写下"设计应该怎样"。期望值从接口契约推导，不从另一份实现抄。

这两种比法能抓住的错误不一样。拿两份实现互比，只能看出"两者不同"，看不出"两者都错"；从规格推导期望值，抓的是实现和契约不符，也就是设计 bug 本身。

## 安装

零运行时依赖，Python 3.9 以上：

```bash
pip install specdiff
```

从源码：

```bash
git clone https://github.com/manhkhiemhoang2-bit/-specdiff_
cd specdiff
pip install -e ".[dev]"
pytest -q
```

## 快速开始

看波形里有什么：

```bash
specdiff info sim.vcd
```

```
文件      : sim.vcd
时间精度  : 1ps
信号数量  : 12
真实跳变  : 223
伪事件    : 3（重发当前值，已忽略）

信号                                       位宽       跳变
--------------------------------------------------------
tb.clk                                        1         86
tb.dut.count                                  8         40
```

再确认时钟和复位认得对不对：

```bash
specdiff index sim.vcd
```

```
时钟      : tb.clk
周期      : 10ps（10000 fs）
采样边沿  : 上升沿
复位      : tb.rst_n（低电平有效，1 段有效区间）
总周期数  : 43
有效起始  : 第 2 拍（此前的采样点处于复位期，不参与比对）
```

两个都是自动识别的，认错了用 `--clock` / `--reset` 指定。

然后按规格检查：

```bash
specdiff check sim.vcd design.spec.yaml
```

```
通过：4 条契约、160 次断言全部满足（40 个有效周期，前 2 拍因复位屏蔽）
```

出问题时：

```
不满足：14 处违反契约（共 4 条契约、160 次断言，其中 146 次通过）

      周期 契约                   信号                         期望         实际
------------------------------------------------------------------------
       3 使能时每拍加一              count                    0x01       0x09 第 3 位不同
       7 使能时每拍加一              count                    0x0D       0x05 第 3 位不同
```

也可以和标准答案比：

```bash
specdiff diff sim.vcd golden.json --config map.yaml
```

## 怎么写规格

规格是一个 YAML 文件。期望值要从接口契约推导，不要照抄 RTL。照抄的话 bug 会被原样复制进规格，比对永远通过，测不出东西。

```yaml
# 信号别名：把波形里的真实路径映射成好记的短名
signals:
  I_tvalid: dut.I_tvalid
  O_tvalid: dut.O_tvalid
  O_tdata: dut.O_tdata

# 常量：算法参数、图像尺寸之类
const:
  LATENCY: 2

rules:
  # 握手信号必须逐拍精确延迟 2 拍
  - name: 输出延迟2拍
    kind: latency
    cycles: 2
    pairs:
      - [O_tvalid, I_tvalid]
      - [O_tdata, I_tdata]

  # 有效拍上不允许出现不定态
  - name: 输出不得含不定态
    kind: no_x
    signals: [O_tdata]
    when: O_tvalid == 1
```

四类契约：

| 类型 | 语义 | 用途 |
|---|---|---|
| `latency` | 输出逐拍等于 N 拍之前的输入 | 流水线延迟、握手信号 |
| `formula` | 目标信号逐拍满足一个表达式 | 算法结果、状态机输出、计数 |
| `stable` | 约束期内信号不得变化 | 握手保持、协议稳定性 |
| `no_x` | 输出不得出现不定态 | X 传播检查 |

表达式里可用的名字：

| 写法 | 含义 |
|---|---|
| `cur.信号` / `out.信号` / `inp.信号` | 这一拍的值 |
| `prev.信号` | 上一拍的值（第一拍为 `None`） |
| `cyc` | 拍号，从 0 开始 |
| `const.名字` | 规格里定义的常量 |

`in.信号` 不能写。`in` 是 Python 关键字，`in.count` 是语法错误，永远解析不了，用 `cur` / `out` / `inp`。

表达式在受限环境里求值，不能 import，也不能访问文件系统。

## 变异自检

一个检查器如果永远报"通过"，它和不存在没区别。所以有这么一个开关：

```bash
specdiff check sim.vcd design.spec.yaml --selftest
```

```
变异自检：故意改错规格，每条都必须被抓出来
（抓不住的条目说明这个维度没测到东西）

  延迟多算一拍                       报错   50 条   抓住
  延迟少算一拍                       报错   50 条   抓住
  适用条件取反                           无法验证   —— 本数据里该契约从未被违反
  注入 X 到 O_tdata               报错    1 条   抓住
  注入 X 到 O_window              报错   11 条   抓住

鉴别力：5/5 个变异被抓住  -> PASS
```

它故意把规格改错——延迟说成 1 拍、条件取反、公式改成不可能值——再看检查器抓不抓得住。抓不住，说明那个维度的断言是空的。

三种结果分得很清楚：

| 结果 | 含义 |
|---|---|
| 抓住 | 改错了就报错，这条断言有鉴别力 |
| 漏掉 | 改错了还报通过，这个维度的断言是空的，必须修 |
| 不适用 / 无法验证 | 规格里没这类规则，或本数据没触发过该契约（比如全程没有 X） |

`no_x` 没法靠改规格验证，自检会往波形里注入一个 X，确认它被抓住。要验证不定态检查，只有这个办法。

这个做法来自一个真实项目：作者在自研检查脚本里写了 `--selftest`，用七个故意改错的期望（延迟 1 拍、延迟 3 拍、窗口上下左右各偏一行）证明自己的测试有鉴别力。

## 处理过的坑

下面这些是"随手写个脚本"和"能当工具用"之间的差别，每一条都有对应的测试。

位切片和整总线同名共存。ModelSim 在某些设置下把 tb 层的总线拆成一根根线导出（`count [7]`、`count [6]`），同时在 dut 层保留整总线。按名字查信号时要挑到位宽正确的那根，否则比对结果全错；只有切片时，工具会把它们拼回一条总线。

复位期屏蔽。复位有效期间的数据不算错。释放那一拍用严格晚于判定，避免差一拍造成的假警报。

最后一个采样点被丢弃。仿真以 `$finish` 结束时，最后一个时钟边沿之后波形没有记录，而寄存器是在该边沿之后才更新的，这个新值没被 dump 下来。留着它会在结尾取到旧值、报一处假错，所以宁可少比一拍。

`$dumpall` / `$dumpon` 会重发当前值，那是伪事件，不算跳变。

四态逻辑 `x` / `z` 原样保留；"通过"和"判断不了"分开统计，否则报告里的断言数是假的。

值按数值比较，不按字符串，位序、字节序类错误不会看漏。

`when` 为假的拍算跳过，不算通过。

## 和 wave-mcp 的区别

芯片验证领域已经有很好的开源工具，把边界说清楚对双方都有好处。

| | [wave-mcp](https://github.com/Tencent/wave-mcp)（腾讯蓬莱实验室） | specdiff |
|---|---|---|
| 核心能力 | 37 个 MCP 工具，给 agent 读波形 | 按规格检查，定位到具体哪几位 |
| 比对方式 | 两份波形互比（pass vs fail） | 波形 vs 规格推导的期望值 |
| 前提条件 | 需要一份已知正确的波形 | 不需要参照物，第一版就能用 |
| 定位粒度 | 分歧时刻 + 信号排序 | 具体到哪几个 bit |
| 依赖 | pylibfst + pyslang，Linux x86_64 | 零依赖，纯 Python，哪都能跑 |
| 波形格式 | FST 为主（VCD 需转换） | VCD |
| Python | 3.10+，glibc ≥ 2.28 | 3.9+，无平台限制 |
| 规模 | 生产级，225 万信号验证 | 个人项目，120 个测试 |

两个工具是互补的。wave-mcp 管"波形里发生了什么"，specdiff 管"设计是否符合契约"。

手上已经有一份确认正确的波形，用 wave-mcp 的两波形互比更直接；要验证的是"这一版实现对不对"而参考波形还不存在，那就是 specdiff 的场子。

## 支持范围

| | 现在支持 | 计划中 |
|---|---|---|
| 波形格式 | VCD | FST（体积小几十倍） |
| 仿真器 | 任意（只要产出 VCD：ModelSim、Icarus、Verilator…） | 直接驱动仿真 |
| 契约类型 | latency / formula / stable / no_x | 断言库、跨时钟域比对 |
| 时钟 | 单时钟、自动识别 | 多时钟域分别建立周期轴 |
| 标准答案 | JSON（两种结构） | — |

specdiff 不依赖任何特定仿真器，它读的是波形文件。ModelSim 导出的 `.vcd` 和 Icarus 产出的 `.vcd` 一样能用。

## 项目结构

```
src/specdiff/
  vcd.py       波形解析：事件流 → 可查询的信号表
  clock.py     时钟/复位识别、周期重编号（领域知识在这一层）
  diff.py      和标准答案逐拍比对
  spec.py      规格求值：四类契约的执行引擎
  specfile.py  规格文件读写
  selftest.py  变异自检：证明检查有鉴别力
  yamlmini.py  极简 YAML 读取（为了保持零依赖）
  cli.py       命令行入口
tests/         120 个测试
examples/      一个真的埋了 bug 的计数器，端到端可跑
```


## 已知限制

- 只支持 VCD，FST 尚未支持
- 单时钟；多时钟域需分别建立周期轴
- `formula` 表达式用 Python 语法，对非程序员不算友好
- 几何类反解（比如从数据里反推坐标）需要项目专有逻辑，不通用，这类检查仍建议留在项目自己的脚本里
